# AGENTS.md

Одностраничная презентация «Нейросети и агенты: основы» на чистых HTML, CSS и JS: без сборки, зависимостей, линтера и тестов.

## Запуск

Открыть `index.html` в браузере — сервер не нужен. Скрипты подключены обычными `<script>` и связаны через глобальную `window.presentation`; на ES-модули не переводить: по `file://` модули не загружаются.

## Для кого

Страница — для всех, а не только для разработчиков: её должен понять человек, который ни разу не открывал терминал, например бухгалтер.

- Объяснять просто, на обычных вещах. Примеры — из повседневной работы (отчёт, таблица, договор, письмо), программистские — только там, где речь о коде.
- Термин (токен, терминал, MCP, git, путь вида `~/.claude`) при первом появлении в разделе пояснять простыми словами — или обходиться без него.
- Как что-то сделать — показывать через приложение: куда нажать, что выбрать, что появится. Команды терминала и файлы настроек — дополнение для тех, кто работает в терминале, а не единственный путь.
- Куда нажимать в приложении — показывать на скриншоте настоящего приложения. Интерфейс не рисовать и не додумывать.

## Достоверность

Всё содержимое презентации — правда с реальной опорой: возможности и ограничения моделей, термины, названия продуктов, цифры, даты, примеры работы. Ничего не выдумывать и не додумывать «для наглядности». Факт, в котором нет уверенности, — до записи проверить по первоисточнику (документация, публикации разработчиков); проверить не удалось — не писать, а сказать пользователю. Упрощать можно, искажать нельзя: упрощённая формулировка остаётся верной. Иллюстративный пример (диалог, сценарий) допустим, если показывает то, как модели и агенты работают на самом деле.

## Где что править

- Содержимое — разделы, блоки, пункты, тексты — только в `content/presentation.js`, в виде данных. Меню, обложку, оглавление и номера разделов страница строит сама.
- Добавить, убрать или исправить пункт, блок, раздел — значит поменять только данные. `index.html`, `assets/render.js` и `assets/styles.css` ради этого не трогать: нужное выражается существующими типами блоков и состояниями. Если без нового типа блока, разметки или стиля не обойтись — сначала предложить это пользователю, а не менять молча.
- Схема данных (поля разделов, типы блоков и их поля) описана в шапке `content/presentation.js`. Новое поле или тип блока — тем же изменением дописать туда.
- Новый тип блока: функция отрисовки в `assets/render.js` и запись в `BLOCK_RENDERERS`, раздел `/* ---------- <тип>: … ---------- */` в `assets/styles.css`, строка в шапке `content/presentation.js`.
- Снимки экрана — файлы в `assets/screens/`; в данных блок `screen` ссылается на них путём от `index.html`.
- Иконки — ключи `ICON_PATHS` в `assets/render.js`: контур в сетке 24×24, заливка не рисуется (`.icon` — `fill: none`, `stroke: currentColor`).
- `basis.md` — план тем презентации.

## Тексты

Весь текст из данных экранируется: HTML в содержимом не работает. Разметка внутри текста — только `**выделение**` и `` `код` ``, и не во всех полях (список — в шапке `content/presentation.js`).

## Стили

- Тема одна, тёмная. Цвета — только переменные `--color-…` из `:root`, литералов цвета в правилах нет.
- Раскладка блока подстраивается под ширину самого блока через `@container` (у `.block` задан `container-type`), а не под экран: блок в полширины узок и на широком мониторе. `@media (max-width: 900px)` — только для каркаса страницы, меню и сетки блоков.
- Состояния — классы `is-accent`, `is-muted`, `is-spotlight`, `is-warning`; в данных им соответствуют булевы поля `isAccent`, `isMuted`, `isSpotlight`, `isWarning`.
